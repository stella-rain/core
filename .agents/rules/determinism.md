# Determinism rules

The same stage, seed and inputs must give the same state hash every tick, on x86_64 and arm64
(ADR-SIM-1, ADR-SIM-3). Phones record on ARM, CI verifies on x86; a break fails stages.

## Simulation code and state

- Fixed timestep, 60 ticks per second. Nothing depends on frame time or the wall clock.
- Fixed-point integers for positions, velocities and angles (for example 1/256 pixel units),
  no `f32` or `f64` in simulation state; trigonometry through lookup tables. Explicit integer
  widths: no `usize` or `isize` in simulation state or in the hash.
- SplitMix64 written in `core` (ADR-SIM-2), never a crate, seeded from the run setup, one stream
  per purpose: `State.rng` holds four, spawn, attack, loot, horde (`rng::derive(seed, TAG_*)`,
  one SplitMix64 step of `seed ^ tag`, `src/rng.rs`), hashed in that order. The offer generator
  is each career's (`Career::offer`): slot 0 `TAG_OFFER`, slot 1 `TAG_OFFER_1`, slot 2
  `TAG_OFFER_2`, hashed in that player's block. `sim_v1` keeps its five-field `Streams`. A
  draw goes on the stream of the system that decides how many draws happen. The number, order
  and stream of draws are frozen per `sim_version`. No other randomness: no thread RNG, time,
  pointer addresses or thread scheduling.
- The crit roll takes no draw: it hashes `crit_seed`, the tick, `roll_key(id)`, hp and the hit
  point (`src/sim/combat.rs`). `State::roll_key` (`src/sim/entity.rs`) is `to_compact(id, id_gap)`
  (`src/id.rs`), read by the crit roll and the push-apart angle (`src/sim/push.rs`): a player's
  number of any generation maps to its slot, every other entity `id_gap = MAX_PLAYERS - present`
  lower (2, 1, 0 for 1, 2, 3 players). A join or leave moves the gap at once: every live enemy's
  key shifts by one per slot gained or lost, its next crit roll and push angle read the new key,
  later spawns use the count then (ADR-SIM-8). The hash and savepoint write numbers as they are.
- Collision is our own code (circle vs point, circle vs circle); no engine physics. Entities
  live in `Vec`s with stable IDs; never iterate a `HashMap` or `HashSet` in simulation code.
- `overflow-checks = true` in every Cargo profile, release included. Where overflow is possible,
  use `saturating_*` or `wrapping_*`; any other overflow panics, the panic is caught at the gdext
  boundary and the run ends (fail closed).
- One input per present slot per tick is the only external influence.
- A state hash per tick covers the full state: FNV-1a 64 over an explicit byte encoding that `core`
  writes itself, never `DefaultHasher` or a derived `Hash`; prefix-free within a mode (a `timed`
  run's hash ends with a tail a `stop` run's lacks). Layout: `state-hash.md`. The bans on floats
  and hash-iteration types (ADR-SIM-1, ADR-SIM-3) are lints in `clippy.toml`.

## `sim_version` (ADR-REPL-1)

- `sim` runs the newest `sim_version`; `sim_v1` is the frozen copy of version 1 (`Run::V1`,
  `src/engine/run.rs`). The engine fails closed on any other version; version 0 files, packs
  and replays are refused.
- A change that can alter an outcome is `sim_version` N+1 and branches on it where behaviour
  differs (`if version >= N+1`, with a comment `sim_version >= N+1: <why>`); the older branch
  stays byte for byte. Fixing a bug in older behaviour is an outcome change: gated, never
  edited in place. The `schema-change` skill has the steps.
- A gate is enough when the older branch is untouched, the state layout and hash encoding
  below N+1 are unchanged, the schedule's steps and order below N+1 are unchanged, every frozen
  case replays with identical hashes and a test at N+1 shows the new behaviour. A full copy
  (`sim_vN+1`) is for a rewrite only: those cannot hold, or one version needs more than 12
  gates (above it Kade picks gates or a copy).
- The frozen corpus `tests/corpus/v<N>/` guards the older versions. An edit to `sim` that moves
  an older hash is red and cannot be blessed away: revert, gate or copy.
- Shared leaf code (fixed point, trigonometry, RNG, hash) stays outside `sim` and is pinned by
  golden tests. Changing its behaviour is a new function beside the old, called from a gate;
  the old one and its golden test stay while a version uses it.
- Frozen rules include the state hash and its byte encoding (ADR-SIM-3 point 1), and the dynamic budget
  caps with their overflow rules (ADR-SIM-5 point 2): raising a cap is a new `sim_version`.

## Tests

- The corpus (`replay.md`): `tests/corpus/current/` is regenerated by `cargo xtask bless`, the
  frozen `tests/corpus/v<N>/` never changes. Every PR re-simulates it on x86_64 and arm64 and a
  mismatch reports the first diverging tick. The device corpus runs after a release (ADR-REL-6, ADR-PLAT-10; ADR-SIM-3 point 4).
- `proptest` invariants (`tests/properties.rs`, `PROPTEST_CASES=2000`): same input, same hash;
  HP rises only by a heal; statuses expire; positions stay in bounds.
- Budgets (ADR-SVC-1): the validator and runtime clamps; test at the limit and one past it.
- A new dependency in the simulation path is checked for floats, hash ordering and
  platform-dependent behaviour first, and named in the commit body.
