# Determinism rules

The same stage, seed and inputs must give the same state hash every tick, on x86_64 and arm64
(ADR-SIM-1, ADR-SIM-3). Replays are made on ARM phones and verified on x86 CI; a break here makes
published stages fail to verify.

## Simulation code and state

- Fixed timestep, 60 ticks per second. Nothing depends on frame time or the wall clock.
- Fixed-point integers for positions, velocities and angles (for example 1/256 pixel units).
  No `f32` or `f64` in simulation state; trigonometry through lookup tables.
- Explicit integer widths: no `usize` or `isize` in simulation state or in the hash.
- SplitMix64 written in `core` (ADR-SIM-2), never a crate, seeded from the run setup, one stream
  per purpose: spawn, attack, loot, offer, horde (`rng::derive(seed, TAG_*)`; `State.rng` holds
  the five). A draw goes on the stream of the system that decides how many draws happen. The
  number, order and stream of draws are frozen per `sim_version`; each stream's state is hashed.
  No other randomness: no thread RNG, time, pointer addresses or thread scheduling.
- Collision is our own code (circle vs point, circle vs circle); no engine physics.
- Entities live in `Vec`s with stable IDs. Never iterate a `HashMap` or `HashSet` in
  simulation code; use `Vec`, `BTreeMap` or sorted keys.
- `overflow-checks = true` in every Cargo profile, release included. Where overflow is possible,
  use explicit `saturating_*` or `wrapping_*` operations; any other overflow panics, the panic is
  caught at the gdext boundary and the run ends (fail closed).
- One input record per tick is the only external influence.
- A state hash per tick covers the full state. It is FNV-1a 64 over an explicit byte encoding
  that `core` writes itself; never `DefaultHasher` or a derived `Hash`.
- ADR-SIM-3 enforces the float, `usize`/`isize` and hash-iteration bans as lints (for example
  clippy `disallowed-types`); add them when the crate is created.

## `sim_version` (ADR-REPL-7)

- One module, `sim`, holds every released `sim_version`. The engine runs `v @ 1..=SIM_VERSION`
  through it and fails closed on any other version. Version 1 is the frozen first version
  (the freeze, FZ1); version 0 files, packs and replays are refused.
- A change that can alter an outcome is `sim_version` N+1 and branches on it where behaviour
  differs (`if version >= N+1`, with a comment `sim_version >= N+1: <why>`); the older branch
  stays byte for byte. Fixing a bug in older behaviour is an outcome change: gated, never
  edited in place. The `schema-change` skill has the steps.
- A gate is enough when the older branch is untouched, the state layout and hash encoding
  below N+1 are unchanged, the schedule's steps and order below N+1 are unchanged, every frozen
  case replays with identical hashes and a test at N+1 shows the new behaviour. A full copy
  (`sim_vN+1`) is for a rewrite only: those cannot hold, or one version needs more than 12
  gates (above it Kade picks gates or a copy).
- The frozen corpus `tests/corpus/v<N>/` guards the older versions. An edit to `sim` that moves
  an older hash is red and cannot be blessed away: revert, gate or copy.
- Shared leaf code (fixed point, trigonometry, RNG, hash) stays outside `sim` and is pinned by
  golden tests. Changing its behaviour is a new function beside the old, called from a gate;
  the old one and its golden test stay while a version uses it.
- Frozen rules include the state hash and its byte encoding (ADR-SIM-3), and the dynamic budget
  caps with their overflow rules (ADR-SIM-7): raising a cap is a new `sim_version`.

## Tests

- The corpus holds replays per `sim_version`: `tests/corpus/current/` is regenerated by `cargo xtask bless`,
  the frozen `tests/corpus/v<N>/` never changes; a stage case has the state hash after every tick, a run
  case `checkpoints` every 60th tick. Every PR re-simulates it on x86_64
  and on an arm64 runner; a mismatch reports the first diverging tick and dumps both snapshots. The Android device run is a release gate (ADR-REL-3).
- `proptest` invariants (`tests/properties.rs`): same input gives the same hash, HP rises
  only by a heal and never above its start, statuses expire, positions stay in bounds.
- Budgets (ADR-SVC-1) are enforced twice, by the validator and by runtime clamps; test at the
  limit and one past it.
- A new dependency in the simulation path is checked for floats, hash ordering and
  platform-dependent behaviour first, and named in the commit body.
